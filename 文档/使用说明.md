# Minecraft AI 建造助手 — 使用说明

一个会自己走到你身边、按你的要求搭建筑的 Minecraft AI（本地单人服务器，创造模式 + 超平坦世界）。

> **术语**：本文里 **ai**（小写）指**游戏里的 AI 机器人**（默认名字 `world`）；
> **AI**（大写）指**开发这个项目用的 AI**。文档靠大小写区分两者。
> 开发协作约定见 `AGENTS.md`。

---

## 一、启动

双击 **`脚本\启动.bat`** 即可。它会自动完成：启动本地服务器 → 等待世界加载 → 启动 AI。**不要关闭弹出的黑色窗口**（那是服务器/AI 的日志，关掉就断开了）。结束后在黑窗口按 Ctrl+C，服务器会自动关闭。

只想**单独启动 ai**（服务器已经在跑）时，在项目目录执行 `npm start`（等价于 `node 源码\bot.js`）。

### 用软件面板（网页界面，最省事）

双击 **`脚本\启动面板.bat`**（等价于 `npm run panel`），浏览器会自动打开 `http://127.0.0.1:8787/`。
面板能干的事：**一键起停服务器 / ai**、实时看两边输出、往服务器控制台发命令、改 `config.json`
（保存后重启 ai 生效）、看 `日志/` 与 `服务器/logs/`、管理 `蓝图/` 和 `教学/`、看本机 **性能**。

几个页面怎么用：

- **启动 / 停止**：左边服务器、右边 ai。ai 那栏会**列出全部 ai**（主 ai + 游戏里 `summon` 出来的），
  但起停只针对主 ai；单个删除在游戏里用 `summon <名字> del`。两张卡的按钮行和输出框高度一致，
  输出框固定大小、自动滚到底；页面每 2 秒拿一次状态，**只有数值真的变了才重画**
  （正在输入时不会被打断），所以不会再有"整块闪一下"的感觉。
- **连接与权限**：
  - **多个服务器分页**：一个分页 = 一套"服务器 / RCON / ai"配置。`+ 新建分页`（可从当前页复制）、
    `改名`、`删除`、**`应用到游戏`**（把这一页写进 `config.json`，然后重启 ai 生效）。
    只是切到别的分页改配置**不会**动 `config.json`，所以不会误改正在跑的 ai。
  - **视角在建页时选定，之后不能改**：点 `+ 新建分页` 时会出现一行「名字 + 视角（我是服主 / 我是成员）」，
    建完这一页的视角就**锁死**（一台机器上谁是服主是固定的）。页面顶部会显示
    "本页视角：服主/成员（创建分页时选定的，之后不能改 —— 要换视角就新建一个分页）"。
    以前那种来回切的按钮已经去掉；老分页（建的时候还没有这个字段）会提示**补选一次**，选完同样锁死。
  - **服主视角**：填「服主游戏名」（`ai.owner`）后，成员进服就会被记成成员；
    下面是**玩家登记表**（谁进过服、角色、**初始 ai 名（固定）**、**别名**、名下的 ai、最后在线），
    以及 **ai 一览**（改「谁能指挥」= `obey` 名单，改完立即生效）。
    - **初始 ai 名固定**：成员 = `way-<玩家名>`，服主 = 主 ai（`world`），**不能改名**；
      想换个好叫的名字就在「别名」那一列填（例：`小A`），游戏里 `小A build ...` 和
      `way-alice build ...` 效果一样。别名不能和主 ai 名 / 别人的名字 / 场上已有 ai 名撞。
    - **玩家表里只列人**：名字带 `way-` 前缀的、或者在 `ais.json` 里的（`world` / `AIBuilder` / `way-xxx`）
      一律算 **ai**，不会混进玩家表；历史上误记进去的，面板打开时会自动清掉并提示"已把 N 个其实是 ai 的名字清出去"。
      归属优先看 `ais.json` 的 `owner`，没有就按名字推（`way-alice` → `alice`），推出来的会标「（按名字推断）」。
  - **聊天监视（服主）**：玩家登记和 ai 一览之间多了一块聊天窗口（最近 40 条，4 秒自动刷新，可暂停）。
    - **能看到每个 ai 的聊天**：顶部「只看：」可以选某个 ai；下面还有一行
      「每个 ai 的记录（共 N 个）：way-alice（小A）→ alice：12 句，最后一句「…」」
    - ai 每收到一条聊天都会写进 `日志/聊天.log`，面板只读这个文件；ai 自己说的话会**高亮**
      并标出「（别名 小A）（属于 alice）」—— 新 `summon` / 手动起的 ai 上线后说第一句话就能看到它归谁。
  - **非服主（成员）视角**：**只显示自己能设置的部分**，看不到服主的任何设置（服务端直接不下发，不是灰掉）：
    1. **我的连接**：服务器地址 / 端口 / 版本 / 登录方式 / 正版账号 / RCON / 行为 / 默认建筑 —— 都能改；
    2. **我的初始 ai**：名字**固定**（`way-<你的游戏名>`，只读）+ **别名**（可改）；
    3. **我的 ai 与指挥白名单**：只有你自己名下的 ai，可改「谁能指挥」；
    4. **我的 ai 聊天**：只显示你自己和你名下 ai 的发言。
    服主的游戏名 / 主 ai 名 / 成员 ai 前缀 / op 策略 / op 白名单 / 别人的登记都看不到（也改不了，服务端 403）。
    别名改完**立即生效**（ai 每条聊天都会重读登记，5 秒缓存）；初始 ai 的名字不用改，也改不了。
  - 玩家和 ai 归属是**游戏里自动记的**（`源码/玩家登记.js` 写 `配置/玩家登记.json`，
    ai 归属读 `ais.json`），面板只负责展示和修改，不需要手填名单。
- **性能**：**默认关闭**（采样要起一次系统命令，一直开着纯属白占 CPU）。在页面上点「开启性能检测」
  才开始：整机 CPU（含每核）/ 内存 / 项目所在磁盘，**面板自己**的 CPU 与内存（RSS / 堆 / 已运行），
  以及**每一个 ai** 和 Minecraft 服务器的 CPU / 内存 / 已运行时间，2 秒刷新；切到别的页面自动停。
  第一次打开时进程 CPU 显示"—"（要两次采样相减），2 秒后就有数。
  Windows 上进程的 CPU 靠 PowerShell 的 `Get-Process` 读（`wmic` 已被微软移除）；没有 PowerShell 就只显示内存。
  开关会记住（存 `配置/面板设置.json`，和游戏的 `config.json` 分开）。
  服务器和 ai 都跑在这台电脑上，游戏卡的时候先看这里哪一行最大。

- 面板只监听本机 `127.0.0.1`，**不会暴露到局域网**（它既能改配置又能起停进程，别改成 0.0.0.0）。
- **关掉面板窗口 = 停掉面板自己启动的服务器和 ai**（服务器会先收到 `stop`，存档正常保存）。
  你自己用别的窗口开的服务器，面板只会显示"不是面板启动"，不会去停它。
- 改了 `源码/panel/api/` 里的**功能文件**（不带下划线的），点左下角 **"热重载功能"** 即可，不用重启面板。
  下划线文件（`_util` / `_state` / `_procs` / `_fields` / `_profiles` / `_settings`）是共享底座，改完要**重启面板**；
  改 `web/` 下的前端文件刷新浏览器就行。
- 面板的 `配置/` 目录（服务器分页、玩家登记、面板设置）**不进 Git**：换机器会重新生成，想搬家就手动拷这个目录。
- 面板和 `脚本\启动.bat` **二选一**：两边同时起 ai 会因同账号重复登录互相踢。


进游戏后连 **`localhost`**（或 `127.0.0.1`）即可。

> 进入世界的玩家会被**自动授予 op 权限**（已授权的名单存在 `ops.json`，重启后依然有效），
> 可以直接使用 `/gamemode`、`/tp` 等指令。
> 这个行为只对**本机自建服**生效（`config.json` 的 `ai.autoOp` 默认 `local-only`）；
> 连别人的服务器时**谁都不会被 op**，详见下面"连自己的服务器（或朋友的服）"。

> 首次运行会自动下载 Minecraft 1.21.1 服务端（为了兼容本机 Java 21），需要联网，请耐心等。

### 连自己的服务器（或朋友的服）

**改 `config.json` 的 `server` 段**就行，不用翻代码：

```json
{ "server": { "host": "play.example.com", "port": 25565, "version": "auto", "auth": "offline" } }
```

| 键 | 填什么 |
| --- | --- |
| `host` / `port` | 服务器地址 / 端口（默认 25565） |
| `version` | 服务器版本；不确定就写 `"auto"`（连上时自动探测，要求服务器 `enable-status=true`） |
| `auth` | 服务器是**离线模式**（`online-mode=false`）填 `"offline"`；是**正版验证**填 `"microsoft"` |
| `username` | 只在 `auth: "microsoft"` 时用：正版账号的**邮箱** |
| `profilesFolder` | 正版令牌缓存目录，留空 = `服务器/nmp-cache`（下次启动免登录） |

**只想临时连一次**（不改文件）：命令行参数覆盖一切，`node 源码\bot.js --help` 看全部：

```powershell
node 源码\bot.js --host play.example.com --version auto --no-rcon
node 源码\bot.js --host mc.example.com --auth microsoft --server-user you@mail.com
```

#### 正版服（online-mode=true）怎么登录

`auth` 改成 `"microsoft"` 后启动，控制台会打印一个**设备码**：

```
=============== 正版登录（只需一次）===============
 ① 打开: https://www.microsoft.com/link
 ② 输入: ABCD-EFGH
==================================================
```

浏览器打开链接、输入码、用**拥有 Minecraft 的微软账号**同意一次即可。令牌会缓存
（`服务器/nmp-cache`），以后启动直接进服。

正版服的两个限制：

- **进服名字由账号决定**，`ai.name` 不再是游戏内名字。指令前缀要用**账号名**
  （启动日志会打印 `游戏内名字 = xxx`）。
- **不能 `summon` 多个 ai**：它们共用同一个账号，一上线就会互相踢下线（代码里已直接拒绝）。

#### 接别人的服，三件事一定要注意

1. **指令白名单** `ai.obeyWhitelist`：填**允许指挥 ai 的玩家名**（如 `["Alex", "Steve"]`）。
   空着 = 任何玩家都能指挥 —— 公共服上等于把建造权交给路人。
2. **自动 op** `ai.autoOp`：默认 `local-only`，只有连**本机**自建服时才给玩家 op；
   连外部服务器时**谁都不给**（日志会打印"跳过自动 op"）。确需给别人 op 就改成
   `whitelist`（配合 `opWhitelist`）或 `always`（只在自己开的服上用）。
3. **RCON**：公共服几乎不开放 RCON。拿不到就把 `rcon.enabled` 设成 `false`（或加 `--no-rcon`）：
   `op` / `help` 发书 / 超远距离 `/tp` 不可用，其余功能正常。

另外：**生存服 / 带反作弊的服**会限制飞行和瞬移，AI 的移动与建造会受限、甚至被踢，
建议只在**创造的服**上用。

#### 连不上 / 被踢了怎么办

启动信息会直接给中文原因（规则表在 `源码/access.js`）：

| 看到的话 | 原因 | 怎么改 |
| --- | --- | --- |
| 对方服务器开了白名单 | 你不在服务器白名单里 | 让服主执行 `/whitelist add <ai 名字>` |
| 服务器是正版验证 | `online-mode=true` | `server.auth` 改成 `"microsoft"` 并登录 |
| 版本不匹配 | `server.version` 不对 | 填服务器版本号，或写 `"auto"` |
| 同一个账号在别处登录 | 共用同一个正版账号 | 正版服只能用**一个** ai |
| 对方没有在监听这个端口 | 服务器没起 / 端口写错 | 检查 `host` / `port` |
| 域名解析失败 | 地址拼错 / DNS | 检查 `host` |

白名单 / 封禁 / 版本不符 / 账号被占用这类**改配置才能解决**的错误，ai 会
**停止重连并退出**（不会一直刷日志）；服务器满、网络抖动会自动重连。

### 掉线会自动重连

服务器重启、网络抖一下，ai 会自己重连（1 秒 → 2 → 4 … 最长 30 秒一次），不用你再开一遍。
不想这样的话在 `config.json` 里把 `behavior.reconnect.enabled` 设为 `false`。按 Ctrl+C 退出时不会重连。

### 日志在哪

每次运行都会在 **`日志\ai_<名字>.log`** 留一份完整输出（主 ai 是 `日志\ai_world.log`）。
"刚才到底报了啥错"直接翻这个文件，不用靠回忆黑窗口。

## 二、聊天指令

> ### ⚠️ 所有指令前面都要加 AI 的名字
>
> 第一个 AI 默认叫 **world**，所以指令长这样：
>
> ```
> world build 40 70 40
> world teach 我的电路
> world help
> ```
>
> 这是**强制**的，哪怕只有一个 AI —— 否则你和朋友正常聊天时冒出个 "build"、
> "stop" 之类的词，AI 就会自作主张动手，很打扰。加了前缀后，AI 只响应明确叫它的那句话。
>
> 召唤更多 AI 后同理：`Bob build xxx`、`world summon Bob del`。

在游戏里直接打字发送（AI 会忽略它自己说的话）。下表的指令都省略了 `world ` 前缀：

| 指令 | 作用 |
| --- | --- |
| `build` | 在**你当前站的位置**建造默认建筑 |
| `build <蓝图名>` | 在你当前站的位置，复现一个已保存的蓝图 |
| `build <x> <y> <z>` | 到 **xyz 完整坐标**建造（例如 `build 40 70 40`）。会在你指定的**那个高度**开工；如果那个位置悬在空中，AI 会用平滑石头临时支撑（见下） |
| `save <名字>` | 进入**保存模式**，把你搭好的建筑存成蓝图 |
| `list` | 列出所有已保存的蓝图与教学 |
| `teach <名字>` | 进入**教学模式**：开始录制你的移动、放置方块、右键交互 |
| `teach stop` | 结束录制并保存（用 `build <名字>` 复现） |
| `del <名字>` | 删除已保存的蓝图 / 教学（同名一起删） |
| `rep <名字> <方向> <间隔> <数量>` | **重复建造**：沿 x/y/z 方向复制多份。`间隔` 是两份之间的空隙，实际步长 = 建筑尺寸 + 间隔；`数量` 填 `-1` 表示无限（用 `stop` 停止）。例如 `rep 房子 x 2 5` |
| `mark y` / `mark n` | 建造前是否用**红/蓝羊毛**在对角标出建造范围（**默认开启**）。标完会拆掉再开工 |
| `help` | AI 给你丢一本**成书**（指令手册），书里写明所有指令的用法 |
| `summon <名字> [皮肤]` | 召唤一个新的 AI，**默认听从发这条指令的玩家**；第三参数可指定皮肤（见下） |
| `summon <名字> del` | 删除这个 AI |
| `summon <名字> add <玩家>` | 给这个 AI 增加一名"听从"的玩家 |
| `tpto` / `tp` | 传送到**你身边**（落在你 5 格内）。`tpto <x> <y> <z>` 传送到指定坐标（如 `tpto 100 70 100`）；`tpto me` 进入**跟随模式**，始终保持在你 5 格范围内移动 |
| `stop` / `cancel` | **紧急停止并重置**：中止正在进行的建造、取消跟随、松开所有移动按键、清空保存模式，让 AI 回到待命状态 |

### tpto 说"找不到你的位置"？

那是因为你超出了 AI 的**可见距离**——服务器不再把你的实体同步给 AI，它拿不到你的坐标
（代码里没有"太远"这句提示，是它会回"找不到你的位置，请靠近一些再试"）。

现在不用管了：AI 发现自己看不见你时，会自动改用服务器 `/tp` 过去（它是 op，不受距离限制），
并告诉你"已用服务器 /tp 直接过去"。实测 250 格外也能准确落到你身边（约 5 格）。
只有跨维度、或 AI 没有 op 权限时才会失败。

### 日志中文还是乱码？

游戏里聊天是正常的，**只有服务器的日志窗口**会乱码——因为 JDK 18+ 默认用 UTF-8 写日志，
而 Windows 中文环境的日志窗口按 GBK 解码。文件本身没坏（用 UTF-8 编码打开就是好的汉字）。

修法是给 JVM 加参数（让服务器按 GBK 输出）：

```
-Dfile.encoding=GBK -Dsun.stdout.encoding=GBK -Dsun.stderr.encoding=GBK
```

- 用本项目启动：跑 `脚本/start_server.ps1` 或 `脚本/启动服务器.bat`（都已带好这些参数）。
- **用 PCL 启动服务器**：在 PCL 的服务器设置 → JVM 参数里填上上面那一串。

### 指令打错了怎么办

常用拼写错误会自动纠正（`bulid` → `build`、`teahc` → `teach`、`hepl` → `help` 等）；
实在看不懂的指令 AI 也会回一句提示，而不是一声不吭。输入 `help` 可以拿到一本指令手册。

### 多个 AI（summon）怎么用

```
summon Bob            → 召唤一个叫 Bob 的 AI，它默认只听你的话
summon Bob add Steve  → 让 Bob 也听 Steve 的
summon Bob del        → 让 Bob 下线
```

**重要：有多个 AI 时，所有指令前面都要加上 AI 的名字**，否则 AI 不知道你在叫谁：

```
Bob tpto              → 只有 Bob 过来
AIBuilder summon Bob del   → 让主 AI 删掉 Bob
```

（指令管理类命令如 `summon ... del / add` 也一样要加前缀。）
**只剩一个 ai 时也照样要加前缀** —— 规则统一，不会因为"只有一个"就免前缀（见第二节开头）。

> 每个 AI 是独立进程，有自己的录制/建造状态，互不干扰。
> 主 AI 启动时会把注册表重置成只有自己，所以重启后旧的子 AI 记录不会残留。

### AI 的皮肤（summon 第三参数）

```
summon 小红 小红皮肤      → 用 skins.json 里登记的"小红皮肤"
summon 小明 https://xx/a.png  → 没登记的会把它本身当皮肤值
summon 小刚               → 不指定，从 skins.json 里随机挑一个
```

皮肤写在 `skins.json`：

```json
{ "command": "/skin set {skin}", "skins": { "小红皮肤": "Notch", "小明皮肤": "https://xx/a.png" } }
```

> **前提**：离线服本身不提供皮肤，要生效服务器得装皮肤插件（最常见的是 **SkinsRestorer**）。
> 这里做的是"登记 + 让 AI 上线后自己执行换肤命令"这一层；没装插件时命令会失败（只记日志）。

### 跟随时会落地

`world tpto me` 跟随过程中，AI 追你的时候飞行，**跟上了（5 格内）就落地站在地上**，
不再一直悬在空中；你走远了它会重新起飞跟上。

### 重复建造（rep）怎么用

```
rep 房子 x 2 5
```

- `房子`：已保存的教学或蓝图名。
- `x` / `y` / `z`：重复的方向。
- `2`：两份之间的**空隙**（不含建筑本身）。实际步长 = 建筑在该方向的尺寸 + 间隔。
- `5`：份数。填 `-1` 表示无限复制，想停就输入 `stop`。

AI 会先算出建筑尺寸（比如宽 3，间隔 2，则每隔 5 格放一份），以你当前位置为起点依次建造。
建造前会先用红/蓝羊毛在对角标出这一份的范围，停顿约 1.5 秒让你看清，然后拆掉再开工——
赶工时可以用 `mark n` 关掉这个标记。

### 传送与跟随（tpto）怎么用

- 想让 AI 立刻到你身边：聊天输入 `tpto`（或 `tp`）。
- 想传送到某个具体地点：输入 `tpto x y z`，例如 `tpto 100 70 100`。
- 想让 AI 跟着你走（你走到哪它跟到哪，始终保持 5 格内）：输入 `tpto me`。
- 任何时候输入 `stop` 即可让 AI 停下跟随之类的动作、并中止正在进行的建造，回到待命。

> 说明：这是"客户端飞行"式传送——AI 会以较快速度飞过去，不是服务端瞬时 `/tp`。长距离传送会花几秒钟，属正常现象。

### 红石粉的点状与十字

红石粉（红石）有**点状**和**十字**两种形态，可以**右键**互相切换。AI 会区分它们：
录制和蓝图保存时都会记下当前形态，复现时会还原（不一致就右键切一次）。

### 教学模式：让 AI 学会你的操作（teach）

蓝图只能记录"最终长什么样"，而**教学模式记录的是过程**——你走过的路、什么时候放哪块、什么时候右键交互，全部按顺序记下来。

1. 聊天输入 `teach 我的电路`
2. 然后正常操作：**走动、放方块、右键点拉杆/按钮**……AI 会在后台记录
3. 做到某个阶段想让 AI 核对一下，输入 **`teach ckpd`** 设一个**检查点**
   （会把到目前为止放过的方块记一份快照，复现进行到此处时核对并修正）
4. 操作完输入 `teach stop`（或 `stop`）结束并保存
5. 想复现时，站到新位置，输入 `build 我的电路`

> 打开聊天框（打字/发指令）的那段时间不会被记录进去。
> 检查点可以在一段录制里设多个；不复现结束后的统一检查，只在你设的检查点处核对。

AI 会**按记录的顺序**重走一遍：先沿你的轨迹移动，再逐个放回方块，遇到交互记录就走到当时的位置、按当时的朝向右键一次。

> 记录保存在项目目录的 **`教学/`** 文件夹里。
> 与蓝图同名时，`build <名字>` 会优先按"教学过程"复现。

### 在空中建造（xyz 坐标 + 平滑石头辅助支撑）

默认 `build` / `build <蓝图名>` 仍然是"在你脚下的地面上"建。想指定高度就用完整 xyz：

```
build 40 70 40      # 在 (40,70,40) 这个高度开工
```

Minecraft 规定：方块必须**挨着一个已有方块**才能放下去。所以在空中开工时，第一块会因为"六个面全是空气"放不下。这时 AI 会：

1. 从目标位置往下找，确定一根**临时支撑柱**的位置
2. 用**平滑石头（smooth_stone）**自下而上搭起这根柱子
3. 把真正的方块依附柱子放好
4. **立刻把临时柱子全部拆掉**（方块放下后即使失去支撑也不会掉落）

所以你看到的结果是：建筑稳稳停在空中，地面到建筑之间**不残留任何东西**。

> 只有"确实悬空"的格子才会触发支撑；一旦有相邻方块，后续方格就能互相依附，不会每块都搭柱子。

### 保存建筑（save）怎么用

1. 聊天输入 `save 我的房子`
2. 在你的建筑**地面层的两个对角**各放一个 **金块（gold_block）** 和 **钻石块（diamond_block）**
3. 放完第二个的瞬间，AI 自动扫描这个长方体区域并保存
4. 之后用 `build 我的房子` 就能在任何位置复现

> 金块/钻石块本身不会被记录进蓝图（它们只是标记）。

## 三、配置文件（config.json）

所有可调项都在项目根的 **`config.json`**（改完重启 ai 生效）。它是**分段**的，只改你关心的那段，
没写的键会自动用默认值（所以别怕删）。

```json
{
  "server":   { "host": "localhost", "port": 25565, "version": "1.21.1",
                "auth": "offline", "username": "", "profilesFolder": "" },
  "rcon":     { "enabled": true, "host": "127.0.0.1", "port": 25575, "password": "minecraft" },
  "ai":       { "name": "world", "autoOp": "local-only",
                "opWhitelist": [], "obeyWhitelist": [] },
  "behavior": { "markOnBuild": true, "reconnect": { "enabled": true, "maxDelayMs": 30000 } },
  "building": { "building": "house", "size": 5, "height": 3,
                "floor": "stone", "wall": "oak_planks", "roof": "bricks" }
}
```

| 段 | 键 | 说明 |
| --- | --- | --- |
| `server` | `host` / `port` | 连哪台服务器 |
| | `version` | 服务器版本；不确定就写 `"auto"`（自动探测） |
| | `auth` / `username` / `profilesFolder` | 离线服 `"offline"`；正版服 `"microsoft"` + 账号邮箱（见上一节） |
| `rcon` | `enabled` | 没有 RCON 权限就设 `false`（op / help 发书 / 远距离 tp 会不可用） |
| | `host` / `port` / `password` | 与 `服务器/server.properties` 里的 `rcon.*` 一致；`password` 留空会自动去读 `server.properties` |
| `ai` | `name` | 主 ai 的名字（游戏里指令前缀就是它；正版服由账号决定，这个只当日志名） |
| | `autoOp` | 自动 op 策略：`local-only`(默认，只给本机自建服) / `never` / `whitelist` / `always` |
| | `opWhitelist` | `autoOp: "whitelist"` 时，这些人进服会被 op |
| | `obeyWhitelist` | **谁能指挥 ai**；空 = 所有人（公共服请填上） |
| `behavior` | `markOnBuild` | 建造前是否用红/蓝羊毛标范围（等同 `mark y/n` 的默认值） |
| | `reconnect.enabled` | 掉线是否自动重连；`maxDelayMs` 是退避上限（默认 30 秒） |
| `building` | `building` | `house` 房子 / `tower` 塔 / `pyramid` 金字塔 |
| | `size` / `height` | 底面边长（建议奇数，更对称）/ 墙的高度 |
| | `floor` / `wall` / `roof` | 地板 / 墙体 / 屋顶材质 |

材质用 Minecraft 的英文方块名（如 `stone`、`oak_planks`、`bricks`、`glass`）。

> **旧格式也能直接跑**：顶层直接写 `building`/`size`/`height`/`floor`/`wall`/`roof` 的老文件会被自动搬进 `building` 段。
> **优先级**：命令行参数 > 环境变量 > `config.json` > `服务器/server.properties` > 内置默认值。
> 环境变量：`MC_HOST` / `MC_PORT` / `MC_VERSION` / `MC_AUTH` / `MC_USER` / `MC_AUTO_OP` / `MC_OBEY`(逗号分隔) / `MC_RCON_PASSWORD`
> （`summon` 出来的子 ai 就是用 `MC_USER` 传名字的）。
> 命令行：`node 源码\bot.js --help` 有完整列表（`--host` / `--port` / `--version` / `--auth` /
> `--server-user` / `--name` / `--auto-op` / `--op-whitelist` / `--obey` / `--rcon-*` / `--no-rcon` / `--no-reconnect`）。

### 有朝向的方块（活塞 / 观察者 / 发射器 / 楼梯…）

这类方块**摆放时的朝向由 AI 当时的视线方向决定**，以前 AI 是悬在方块正上方往下看着放的，所以活塞全都朝上/朝下。现在已修正：

- **墙上的方块默认朝外**（背离建筑中心）——墙里放活塞就会朝外推
- **地板 / 屋顶默认朝上**
- **想自己指定**：在材质名后加 `:朝向`，例如

```json
"wall": "piston:west",
"floor": "observer:up"
```

朝向可填 `north` / `south` / `east` / `west` / `up` / `down`。

**红石与"贴墙"方块（红石粉 / 墙上红石火把 / 拉杆 …）**
这类方块**不占满一整格**，必须贴在某个面上才放得下（和活塞那种整块方块规则不同），AI 已单独处理：

- 红石粉、直立火把 → 贴在下方的**顶面**
- 墙上红石火把、拉杆、按钮 → 贴在指定朝向那一侧的**墙面**

想明确指定贴在哪，写成 `方块名:面:朝向`：

```json
"wall": "lever:wall:north",
"floor": "redstone_wire:floor"
```

面可填 `wall`（贴墙）/ `floor`（贴地）/ `ceiling`（贴天花板）；省略则由 AI 自动判断（优先贴墙）。

**用 `save` 保存蓝图时会连朝向一起记录**，复现时活塞等方块会保持原来的方向。

## 四、几个重要原理（为什么它这样工作）

### 1. 先找真正的地面，不在"空中"开工
AI 不会简单地把"脚下那一格"当地面——它出生时可能还在半空/正在下落。它会**从自己位置向下逐格扫描，找到第一个实心方块**作为地面，所以无论你站在平地、山坡还是半空，建筑都会正确落在实地上。

### 2. 就近建造 + 手臂长度检查（大建筑也不怕）
AI 先把整栋建筑拆成一份"方块清单"，然后按这个顺序施工：

- **先低后高**：底层一定先建好，保证上面每一格都有东西可以依附（不会出现悬空方块放不下）
- **层内就近**：从上一个方块出发，总是挑**离得最近**的下一格（实测平均间距约 1.04 格）

并且在**放置每一格之前**都会检查自己到那个方块的距离：超过 4 格（手臂够不到）就**先飞到它附近**再放。这样即使是很宽的建筑也不会因为"手不够长"而漏格。

### 3. 只有被自己挡住时才飞起来
AI 默认站在地面上正常建造。只有当某一格**被它自己的身体占着**、放不下去时，才会飞起来/移位重试，直到放下为止。所以它不会一开始就吊在半空不动。

### 4. 走直线优先，遇障碍才绕路
AI 走向你（或走向指定坐标）时，**默认走一条直线**（最短、最平滑，不会左右乱拐、也不会没事就往上飞）。只有直线方向真的被挡住、走不动了，才会启动绕路的 A* 寻路算法。

实测：跨越约 70 格空地，轨迹直线度 **1.02**（1.0 即完全直线），高度全程不变。

### 5. 寻路卡住会自己救自己
如果直线和绕路都走不动（AI 走向你或指定坐标时卡住）：

- **1 秒没移动** → 自动**向上飞 2 格**再继续
- **连续卡住 10 秒** → 吃一个**紫颂果**（会随机传送）强行脱困

全程有 120 秒总超时兜底，不会无限卡死。

### 6. 绝不破坏你的世界
寻路和移动都严格禁止挖方块（内部已关闭"挖路"选项），保存扫描时也是**直接飞到你建筑的正上方**读取，不会走进去把你的建筑撞坏。

### 7. 放置计数
每次建造完成，AI 会报告 **本次放置数** 和 **累计放置数**：

```
建造完成！本次放置 100 个，累计 100 个方块
```

## 五、常见问题

**Q：AI 没反应？**
确认黑窗口里出现 `[AI] ready`，且你是在游戏聊天里发指令（不是命令方块/控制台）。

**Q：`build <x> <z>` 建在了奇怪的高度？**
AI 会保持当前高度飞过去，再用"向下扫描"找真实地面，所以是正常落在地面上的。若那片区域尚未加载（从没去过），可能探测失败——先自己走过去一趟再下指令。

**Q：建筑太大很慢？**
约 0.26 秒/方块（100 格约 26 秒）。尺寸越大越久，属正常现象，黑窗口会打印进度。

**Q：想重新开一个干净世界？**
删掉 `服务器\存档` 文件夹和 `服务器\flat_initialized.txt`，再双击 `脚本\启动.bat`。

**Q：蓝图存在哪？**
项目目录下的 **`蓝图/`** 文件夹，每个蓝图一个 `.json`，可手动复制分享（教学记录在 `教学/`）。

## 六、版本管理（Git）

代码托管在 GitHub **私有库** `YanNuo26/AI-World`，分支 `main`。

```powershell
git status                        # 看改了哪些文件
git add -A
git commit -m "说明这次改了什么"    # 中文提交信息没问题（仓库统一 UTF-8）
git push                          # 凭据已存进 Windows 凭据管理器，正常不会再要求登录
```

- **不入库**：`node_modules/`、`服务器/`（jar / libraries / 存档）、`日志/`。换台机器先 `npm install`，
  服务器用 `脚本\start_server.ps1` 自己起；存档想备份就手动复制 `服务器\存档`。
- 想确认远端到底有什么：`git fetch` 后 `git log --oneline origin/main`。
- 换行由 `.gitattributes` 定：仓库内 LF，`.bat` / `.ps1` 固定 CRLF。
  `.ps1` 带中文注释必须保持 **UTF-8 带 BOM**，编辑器别把它改成无 BOM。
- 凭据失效时（例如在 VS Code 里退出了 GitHub 账号）：重新登录一次，或
  `cmdkey /delete:git:https://github.com` 清掉旧凭据后再 `git push`（会弹一次登录窗）。
