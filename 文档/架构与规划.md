# 架构与规划（长期路线图）

> **本文档定位**：产品形态与长期架构规划，给**开发用 AI** 和服主看。
> - 日常协作约定 → `AGENTS.md`（尽量简短）
> - 踩坑记录 → `AI参考.md`（最重要）
> - 玩家用法 → `使用说明.md`
>
> **术语**：**AI**（大写）= 开发用的 AI（编码助手）；**ai**（小写）= 游戏里的 AI 机器人。

---

## 1. 产品形态（已确认）

- **轻量优先**。软件要小、依赖少、启动快。
- **玩家自己下载到本地**：从 GitHub（**当前是私有仓库，未来考虑开源**）下载后本地运行。
- **每个人跑自己的一份**：
  - 服主跑自己的软件 → 里面是 `world`（管理 ai）
  - 每个玩家跑自己的软件 → 玩家**进入游戏时**，由他自己的软件创建 `way-<玩家名>`
- **本地配置服务器信息**；ai **进入游戏后从 `world` 获取服务器信息**（`world` 是服务器侧的信息权威）。
- **本地 LLM 可选**：用户自己决定要不要下载（不下载也能用指令模式）。
- 目标形态：**下载 → 本地配置 → 进游戏就能用**。

## 2. 角色与命名（已确认）

| 角色 | ai 名字 | 由谁的软件创建 | 权限来源 |
| --- | --- | --- | --- |
| 服主 | **`world`** | 服主自己的软件 | **全部权限**，具体范围由**服主在自己的软件里配置** |
| 玩家 | **`way-<玩家名>`** | 玩家自己的软件（**玩家进入游戏时创建**） | **通过 `world` 获取**，或**向 `world` 提要求**由 world 代执行 |

- 玩家**在该 ai 的白名单内时，这个 ai 才回复他**。
- 现有机制已覆盖一半：`summon` 多 ai、**所有指令必须带 ai 名字前缀**、每个 ai 有 `obey` 听从名单。
- 还差：`world` 固定为管理 ai、`way-<玩家名>` 自动命名、权限委托（world 代执行）、服务器信息下发。

## 3. 分层架构

```
L4 治理与权限   world(管理) + way-<玩家名>(个人) + 白名单 + 权限委托
L3 游戏内行为   生存/创造双模式 · 扮演 NPC(商人/女巫) 对话与交易
L2 智能与对话   自然对话 · 本地 LLM/API · 角色扮演 · JS 脚本接口
L1 运行与分发   外接任意服务器 · 轻量本地软件 · 图形配置界面
```

L1 是底座；L2/L3 依赖它；L4 贯穿全部。

## 4. 九项目标（现状 / 要做）

**① ai 外接到服务器**（L1）
- 现状：**已可接外服**。`config.json` 的 `server` 段（host / port / version / auth）统一配置，
  版本可写 `"auto"` 自动探测；**正版服**支持 `auth: "microsoft"`（设备码登录、令牌缓存）；
  命令行可临时覆盖（`node 源码/bot.js --host xxx --auth microsoft`）；
  断线指数退避重连；连不上 / 被踢有中文诊断（`源码/access.js`），致命错误停止重连并退出。
- 还差：图形界面（⑤）里把这些暴露出来。
- 涉及：`bot.js`、`config.js`、`access.js`、`rcon.js`。

**② 像和真人一样对话**（L2）
- 现状：只有指令式交互，且必须带名字前缀。
- 要做：自然语言 → 意图 → 调现有能力；口语化、带上下文。
- 依赖：⑥（也可先做无 LLM 的意图表降级版）。

**③ 生存与创造都可用（服主决定）**（L3）
- 现状：**只支持创造**（依赖飞行、无限方块、即时放置）。
- 已决策：**生存模式不自主采集** —— 缺资源就**向玩家要**（"所有需求可以跟玩家提"）。
- 要做：抽象"能力供给"层：创造 = 无限物品+飞行；生存 = 背包物品+地面移动+向玩家索求。
- 顺序：先"生存里能对话/只读"，再逐步补生存下的建造行为。

**④ 打包成应用，下载即玩**（L1）
- 现状：需自己装 Node 跑命令。
- 要做：轻量打包（内置/捆绑 Node），一键启动；与 ⑤ 界面一起做。
- 约束：**轻量**，不要塞进大型运行时。

**⑤ 图形配置界面**（L1）
- 现状：手改 `config.json` / `skins.json` / `ais.json`。
- 要做：界面覆盖连接、模式、LLM、皮肤、ai 名单、**world 权限**；配置落盘、可导入导出。

**⑥ 外接本地 LLM 或 API，角色扮演**（L2）
- 现状：**有方案、未实现**。可插拔后端（本地 ollama ≈ 真免费不联网；OpenAI 兼容 API）+ 系统提示词（人设）+ 记事本（持久记忆）。
- 要做：新增 `llm.js`；聊天回路改为"命中指令走原路，否则交给大脑"。
- 约束：**本地 LLM 由用户自行选择性下载**，不能作为必装依赖。

**⑦ 开放游戏接口，用脚本回应玩家需求**（L2）
- 现状：**未做**。但 `build.js` / `movement.js` 已有稳定原子能力，是天然 API 面。
- 已决策：**脚本语言 = JavaScript**（与现有代码同语言，零额外依赖）。
- 要做：把能力封装成脚本 API（`placeAt` / `goTo` / `replayTeaching` / `moveTo` / `digBox` / `say` / `ask`），脚本目录 + 沙箱 + 白名单权限。

**⑧ ai 扮演商人 / 女巫等 NPC**（L3）
- 现状：**未做**。
- 要做：触发条件（靠近/时间/指令）+ 人设切换（多套提示词）+ 交易逻辑（物品交换、价目表）。
- 依赖：⑥ + ③ 的物品栏操作。

**⑨ 服务器管理框架**（L4）
- 见第 2 节。现状已有一半（多 ai + 前缀 + `obey`），补命名、权限委托、服务器信息下发。

## 5. 已确认的设计决策（存档）

1. **生存模式不自主采集** —— 缺资源向玩家要。
2. **脚本接口用 JavaScript**。
3. **分发形态** —— 玩家从 GitHub/私有仓库下载软件到本地，本地配置服务器；ai **进游戏后从 `world` 获取服务器信息**。
4. **world 权限** —— 由**服主在自己的软件中配置**。
5. **way-<玩家名> 创建时机** —— **玩家进入游戏时**，由**玩家自己的软件**创建。
6. **轻量优先** —— 依赖精简；本地 LLM 为可选下载项。
7. **开源策略** —— 未来考虑 GitHub 开源，**当前先放私有仓库**。

## 7. 轻量原则 & 开源准备

- **依赖精简**：核心只依赖 mineflayer 系列；LLM / 皮肤 / 界面按需，不作为硬依赖。
- **配置统一**：所有可选项收敛到 `config.json`，界面只做它的前端。
- **可选组件**：本地 LLM（用户自下载）、皮肤（需服务器插件）。
- **开源前需清理**：私有信息（RCON 密码、内网地址）、日志、`world/`、测试残留；
  并把本文与 `AGENTS.md`、`AI参考.md` 一并整理好（这是给外部贡献者最重要的三份文档）。
